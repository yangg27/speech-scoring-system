# 演讲比赛评分系统

> 多活动 · 多维度 · 多评委扫码评分 · 实时排名 · 去极值计分 · 防代打分 · 一键导出 AI 分析数据包

一套开箱即用的 **演讲/汇报比赛评分系统**，覆盖「赛前配置 → 赛中评分 → 赛后分析」全流程。
纯前端单页应用（无框架、无构建），后端用 Serverless PostgreSQL，**扫码即用、免登录、免装 App**。

```
管理员                      评委                      大屏
  │                          │                        │
  │ 建活动/维度/名单          │ 手机扫码 → 输姓名       │ 投屏实时排名
  │ 看实时排名/导出           │ 滑杆打分 → 提交         │ 5 秒自动刷新
  ▼                          ▼                        ▼
        ┌──────────────────────────────────────────┐
        │   Serverless PostgreSQL（云数据库）        │
        └──────────────────────────────────────────┘
```

## 一、它能做什么

| 角色 | 入口 | 能力 |
|---|---|---|
| **管理员** | 管理台（口令登录） | 建活动、配评分维度、录选手/评委名单、实时排名、深度分析、导出 |
| **评委** | 手机扫码（免登录） | 输姓名 → 选选手 → 滑杆打分 → 提交，可随时改分 |
| **观众/大屏** | 看板链接 | 实时排名、维度均分、评委进度（纯展示，无跳转入口） |

### 核心亮点

- **📱 扫码即用**：评委不用装 App、不用注册，扫码输名字就能打分
- **🔒 防代打分**（可选）：本机设备绑定，一台设备只能评一位评委；换人需管理口令放行
- **📊 去极值计分**：可配「去掉 N 个最高分 / N 个最低分」，**逐维度独立剔除**
- **👥 评委名单管理**：预设名单 + 未提交催收 + **移除评委**（评分不计入统计，数据可恢复）
- **🔍 异常留痕**：同设备多评委 / 同 IP 多评委自动告警（只提示不拦截，避免误伤共用 WiFi）
- **📈 深度分析**：自动生成综合结论、共性失分维度、评委宽松/严格倾向、选手强弱项
- **🤖 AI 数据包**：一键导出结构化数据包，直接丢给任意大模型出分析报告
- **🖥 纯展示大屏**：投屏页面无任何可点击跳转，防止观众点进管理入口
- **🔐 双口令门**：进管理台、删活动均需管理口令 + 二次确认

## 四、计分规则

### 基础算法

每个维度**独立计算**：

```
维度均分 = 该维度所有有效评分的算术平均
           （若启用去极值，先剔除最高/最低分再平均）

选手总分 = Σ (各维度均分 × 该维度权重)
得分率   = 选手总分 / 总分上限
```

### 去极值口径（重要）

「去掉一个最高分和一个最低分」指的是——
**对每位选手、每个维度，各自独立剔除该维度上的极端分**。

举例（某选手的「主题内容」维度，13 位评委打分）：

```
全部打分: 13.5, 15, 20, 20, 20, 20.5, 23, 23.5, 25, 25, 25, 25, 25
剔除的:   13.5, 15          ← 该维度上最低的 2 个
计分均值: 22.91 / 25        （未剔除时为 21.58）
```

**不是**按评委整场总分剔除，**也不是**全场统一剔除。

**生效条件**：该维度有效票数 ≥ `2 × 剔除个数 + 1`
（例如剔 2 个最低分，需至少 5 位评委打分；不足则不剔除，避免样本过少失真）

### 排名规则

- 按加权总分降序
- **同分并列**：总分相同则名次相同，后续名次顺延；再按出场顺序排列

## 五、防代打分的实现与边界

### 做法

1. **本机设备绑定**：评委首次输姓名后，该浏览器锁定这位评委；
   之后只显示「继续以 X 评分」，换人需管理员口令放行
2. **全量留痕**：每条评分记录设备指纹、IP、归属地、UA、切换记录
3. **异常面板**：管理台自动列出「同设备多评委」「同 IP 多评委」「评委切换记录」

### 诚实的边界说明

- **按 IP 拦截不可行**：会场共用 WiFi 会让所有评委出口 IP 相同，拦截 = 全场只能一人评分。
  因此 IP 只做**留痕告警**，并明确标注「共用 WiFi 属正常现象」
- **设备指纹可被绕过**：清缓存 / 无痕模式即可重置绑定。
  这套机制的目的是**提高造假门槛 + 留下可追查的线索**，不是万无一失的防护
- 需要绝对防冒名时，应接入**用户登录**（本项目预留了扩展空间）

## 七、技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | 原生 JS 单页应用 | 无框架、无构建、无 npm 依赖 |
| 路由 | hash 路由 | `#/admin?e=1`，静态托管友好 |
| 后端 | WorkBuddy 云服务 | Serverless PostgreSQL + PostgREST |
| 依赖 | 全部本地化 | `vendor/` 目录，不依赖 CDN，内网可用 |

**为什么不用框架**：评委手机扫码打开要快，无构建 = 无版本地狱，
一个 130KB 的 `app.js` 比一堆依赖更可靠。
